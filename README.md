# Бот для продажи гайда «Не баночки, а логика»

Telegram-бот сам продаёт гайд за 490 ₽ через ЮKassa и пускает в закрытый канал **только тех, кто оплатил**.
Тем, кто пытается зайти без оплаты, бот отказывает и сразу предлагает купить.

## Как это работает

```
Google-документ ──ссылка──▶ Бот ──▶ «Купить за 490 ₽» ──▶ email для чека ──▶ оплата в ЮKassa
                                                                             │
                ЮKassa сообщает боту: «оплачено» (webhook + проверка каждые 30 сек)
                                                                             ▼
             Бот присылает ЛИЧНУЮ ссылку в канал ──▶ человек жмёт «Подать заявку»
                                                                             ▼
          Бот проверяет по базе Telegram-ID: оплатил → впускает · не оплатил → отклоняет
                                                    и пишет: «Гайд стоит 490 ₽, купить можно тут»
```

**Почему доступ нельзя «переслать подруге»:**
- Ссылка в канал работает только через заявку, а каждую заявку проверяет бот по Telegram-ID. Если подруга откроет ту же ссылку, бот её не пустит и предложит купить.
- Сообщение со ссылкой защищено от пересылки.
- Личная ссылка возврата из оплаты (`t.me/бот?start=acc_...`) привязана к аккаунту покупателя. С другого аккаунта она не сработает.
- В самом канале включён запрет на пересылку, копирование и сохранение.

**Статусы заказа в базе:** `new` (ждём оплату) → `paid` (ЮKassa подтвердила) → `issued` (ссылка выдана).
Ещё бывают `canceled` (платёж отменён или истёк) и `revoked` (доступ забран вами).

> Честное предупреждение. «Запрет копирования» в Telegram блокирует пересылку, копирование текста и сохранение файлов,
> а в мобильных приложениях ещё и скриншоты. Но в компьютерной версии снимок экрана сделать можно, и сфотографировать
> экран другим телефоном тоже. Полностью защититься от этого нельзя ни в одном сервисе.

## Пошаговая настройка

Займёт около часа. Делайте по порядку.

### Шаг 1. Бот в @BotFather

Бот у вас уже есть, нам нужен только его **токен** (пароль бота).

1. Откройте в Telegram **@BotFather**.
2. Отправьте `/mybots` → выберите своего бота → **API Token**.
3. Скопируйте строку вида `1234567890:AAH...`. Это `BOT_TOKEN`.
   ⚠️ Токен — как пароль. Никому его не показывайте.
4. Желательно (необязательно): там же **Edit Bot → Edit Description**. Здесь текст, который человек видит до нажатия «Старт».
   Например: «Здесь можно купить гайд по выбору ухода за волосами по составу».

> Если бота не было бы: `/newbot` → придумать имя → придумать адрес, оканчивающийся на `bot` → получить токен.

### Шаг 2. Настройка приватного канала

Откройте канал → нажмите на название → **Изменить** (карандаш).

1. **Тип канала** → должно стоять **Частный**.
2. Там же включите **«Запретить копирование»** (в некоторых версиях: «Ограничить сохранение контента»).
   Подписчики не смогут пересылать посты, копировать текст и сохранять файлы.
3. **Администраторы → Добавить администратора** → найдите своего бота по адресу (@...) → включите право
   **«Добавление подписчиков»** (оно же «Пригласительные ссылки»). Остальные права можно выключить → **Сохранить**.
4. **Закройте старые входы.** Зайдите в **Пригласительные ссылки** и **сбросьте/удалите** основную ссылку и все,
   которые вы раньше куда-то выкладывали. Иначе по ним можно зайти в обход бота.
   Если хотите оставить основную ссылку, включите для неё **«Заявки на вступление»**. Тогда по ней тоже будет
   проверять бот: не оплатил — не пустит и предложит купить.
5. Если в канале уже есть люди, которые не платили, удалите их вручную в списке **Подписчики**.

### Шаг 3. Ключи ЮKassa

> **Ключей ещё нет, потому что ЮKassa просит сначала показать бота с кнопкой оплаты?** Это нормально.
> Оставьте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` пустыми: бот запустится в **демо-режиме**.
> Он показывает описание гайда и кнопку «Купить за 490 ₽», а при нажатии отвечает, что оплата скоро заработает.
> Отправьте в ЮKassa ссылку на бота и скриншоты, а когда пришлют ключи, впишите их и перезапустите бота.

1. Войдите в личный кабинет **yookassa.ru**.
2. **Сначала тестовый магазин (очень советую).** Вверху слева нажмите на название магазина → **Создать тестовый магазин**.
   В нём можно «оплачивать» тестовой картой без настоящих денег.
3. В нужном магазине откройте **Интеграция → Ключи API**:
   - **shopId** (номер магазина, цифры) → это `YOOKASSA_SHOP_ID`;
   - **Секретный ключ** → нажмите «Выпустить» → это `YOOKASSA_SECRET_KEY`. Ключ показывается один раз, сразу сохраните.
     У тестового магазина он начинается с `test_`, у настоящего с `live_`.
4. **Чеки:**
   - Если вы **самозанятая**, впишите `RECEIPT_ENABLED=false`. ЮKassa сама передаст доход в «Мой налог», а бот не будет спрашивать почту.
   - Если у вас **ИП** и подключены «Чеки от ЮKassa» или онлайн-касса, впишите `RECEIPT_ENABLED=true`. Бот попросит у покупателя email, и ЮKassa пришлёт на него чек.
     `VAT_CODE=1` — это «без НДС». Если сомневаетесь, уточните у бухгалтера.

Настройку уведомлений (webhook) в ЮKassa сделаем в шаге 6, когда будет сервер.

### Шаг 4. Сервер, где бот работает круглосуточно

Бот должен работать постоянно, поэтому ему нужен небольшой сервер (VPS). Он стоит примерно 200–400 ₽ в месяц.

1. Арендуйте VPS у любого хостинга (Timeweb Cloud, Beget, Selectel, REG.RU и т.п.):
   **Ubuntu 24.04, 1 ядро, 1 ГБ памяти** — этого хватит с запасом.
2. Хостинг пришлёт **IP-адрес** (например `85.193.80.12`) и **пароль root**.
3. Подключитесь к серверу. На Mac откройте программу «Терминал», на Windows — «PowerShell», и введите:
   ```
   ssh root@85.193.80.12
   ```
   (подставьте свой IP, на вопрос `yes/no` ответьте `yes`, затем вставьте пароль: при вводе его не видно, это нормально).
4. Скопируйте и выполните по очереди эти команды. Они устанавливают Docker и скачивают бота:
   ```
   curl -fsSL https://get.docker.com | sh
   git clone https://github.com/alina41003-design/-.git guide-bot
   cd guide-bot
   cp .env.example .env
   nano .env
   ```
   > Если репозиторий на GitHub приватный, `git clone` спросит логин и пароль. Вместо пароля нужен токен:
   > GitHub → Settings → Developer settings → Personal access tokens. Проще сделать репозиторий публичным:
   > в коде нет ни одного пароля, все они живут только в файле `.env` на сервере.

### Шаг 5. Заполняем файл настроек `.env`

Команда `nano .env` открыла файл настроек. Впишите после знака `=` (без пробелов и кавычек):

| Строка | Что вписать |
|---|---|
| `BOT_TOKEN` | токен из шага 1 |
| `YOOKASSA_SHOP_ID` | shopId из шага 3 |
| `YOOKASSA_SECRET_KEY` | секретный ключ из шага 3 |
| `RECEIPT_ENABLED` | `false` (самозанятая) или `true` (ИП с чеками) |
| `DOMAIN` | IP сервера через дефисы + `.sslip.io`, например `85-193-80-12.sslip.io`. Если есть свой домен, можно его |
| `CHANNEL_ID`, `ADMIN_IDS` | пока оставьте пустыми, узнаем ниже |

Сохранить: **Ctrl+O**, затем **Enter**, выйти: **Ctrl+X**.

Запуск:
```
docker compose up -d --build
```

Теперь узнаём два ID:
1. Напишите своему боту `/id`. Он ответит вашим Telegram-ID. Это `ADMIN_IDS`.
2. Перешлите боту любой пост из вашего канала. Он ответит ID канала (`-100...`). Это `CHANNEL_ID`.
3. Снова откройте `nano .env`, впишите оба числа, сохраните и перезапустите:
   ```
   docker compose up -d
   ```
4. Проверьте журнал работы:
   ```
   docker compose logs -f bot
   ```
   Там должно быть **«Канал подключён, права в порядке»**. Выйти из журнала: Ctrl+C (бот продолжит работать).

### Шаг 6. Уведомления об оплате (webhook) в ЮKassa

1. ЮKassa → **Интеграция → HTTP-уведомления**.
2. URL для уведомлений: `https://ВАШ_DOMAIN/yookassa/webhook`
   (например, `https://85-193-80-12.sslip.io/yookassa/webhook`).
3. Отметьте события **payment.succeeded** и **payment.canceled** → Сохранить.

> Даже если уведомление когда-нибудь потеряется, бот сам перепроверяет неоплаченные заказы в ЮKassa каждые 30 секунд.
> Покупатель всё равно получит доступ.

### Шаг 7. Ссылка в Google-документе

Поставьте в документ кнопку или ссылку «Купить гайд» с адресом:
```
https://t.me/АДРЕС_ВАШЕГО_БОТА?start=guide
```
(адрес бота без `@`). Не забудьте открыть доступ к документу: **Настройки доступа → Все, у кого есть ссылка → Читатель**.

### Шаг 8. Проверка

Пока стоят ключи **тестового** магазина:
1. С телефона нажмите ссылку из Google-документа → **Старт** → **Купить** → **Оплатить**.
2. Тестовая карта: `5555 5555 5555 4477`, срок — любая будущая дата, CVC — любые 3 цифры, код из СМС — любой.
3. Бот должен прислать «Оплата прошла» и кнопку «Войти в канал». Нажмите её и подайте заявку: бот впустит.
4. Попросите кого-нибудь (или зайдите со второго аккаунта) открыть ту же ссылку в канал. Бот отклонит заявку и пришлёт предложение купить.
5. Вам как админу придёт уведомление «💰 Новая оплата».

Всё работает? Переходите на настоящие ключи: в `.env` замените `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` на ключи
**настоящего** магазина, выполните `docker compose up -d` и повторите шаг 6 уже в настоящем магазине.
Тестового покупателя удалите из канала.

## Команды для вас (работают только с ID из `ADMIN_IDS`)

| Команда | Что делает |
|---|---|
| `/stats` | сколько людей запустили бота, оплатили, выручка, сколько пытались зайти без оплаты |
| `/grant` | одноразовая ссылка-доступ (подарок или оплата переводом): отправьте её человеку, она привяжется к первому, кто откроет |
| `/grant 123456789` | сразу выдать доступ человеку с этим Telegram-ID |
| `/revoke 123456789` | забрать доступ (например, при возврате денег) и удалить из канала |
| `/id` | показать ваш Telegram-ID |

## Частые вопросы

**Как поменять тексты бота?** Все тексты лежат в файле `app/texts.py`. Меняйте текст в кавычках,
а слова в фигурных скобках `{price}` и `{product}` не трогайте. После правки: `docker compose up -d --build`.

**Как поменять цену?** В `.env` строка `PRICE`, затем `docker compose up -d`.

**Покупатель пишет, что оплатил, а ссылки нет.** Пусть нажмёт в боте `/start`: если оплата прошла, бот пришлёт ссылку заново.
Если не прошла, в ЮKassa в разделе «Платежи» будет видно почему.

**Покупатель вышел из канала и хочет вернуться.** Пусть нажмёт `/start` в боте: оплата за ним сохранена, ссылка придёт снова.

**Бот перестал отвечать.** На сервере: `cd guide-bot && docker compose logs --tail 50 bot` покажет ошибку, а
`docker compose restart bot` перезапустит бота. После перезагрузки сервера бот запускается сам.

**Где база заказов?** В файле `data/shop.db` на сервере. Время от времени скачивайте копию.

**Обновить бота после изменений на GitHub:** `cd guide-bot && git pull && docker compose up -d --build`.

## Что внутри (для разработчика)

- `main.py` — запуск: бот (long polling) + веб-сервер для уведомлений ЮKassa + фоновые задачи.
- `app/shop.py` — создание платежа, подтверждение оплаты, выдача персональной ссылки (`creates_join_request=True`).
- `app/handlers.py` — `/start` и deep-link `acc_<token>`, покупка, проверка заявок в канал, команды админа.
- `app/webhook.py` — приём webhook; статус платежа всегда перепроверяется запросом в API ЮKassa.
- `app/tasks.py` — подстраховочная проверка неоплаченных заказов и напоминания.
- `app/db.py` — SQLite: `users`, `orders`, `join_attempts`.
- `tests/` — проверка всего сценария без настоящих Telegram и ЮKassa: `python -m unittest -v`.
